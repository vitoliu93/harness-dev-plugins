# 证据阶梯

判定只认阶梯上最高一层拿到的证据。低层证据可作线索，不作结论。

| 层级 | 手段 | 判定资格 |
|---|---|---|
| 1 DOM 事实 | 元素几何（位置、尺寸）、计算样式、属性 / 文本断言、结构断言 | 可直接判定 |
| 2 截图像素 | 目视或像素扫描 | 只作线索；须回落到第 1 层确认 |
| 3 坐标点击 | 按画布坐标点选 | 不作判定依据；对分层画布禁用 |

## 分层画布

分层画布应用（多层叠放的渲染面）里，一个坐标同时落在多个层上。按坐标点击命中的是
最顶层覆盖物，不是目标元素。表现为：操作「成功」了，但选中的对象不是要验的那个，
后续所有断言都在验错误对象。

必须走应用语义面完成选中：

- 列表行 / 表格行
- 时间线条目
- 树节点
- 图层面板项

选中后再取 DOM 证据。选中态本身也要取证：拿目标元素的属性或类名断言，不靠肉眼看高亮。

像素扫描同样不可靠：画布描边、容器边框、网格线都会被扫成「有框」，产出假 PASS。

## 缺席可能是设计

装饰缺失（选中框、角标、拖拽手柄、悬浮工具条）不等于 bug。判 FAIL 前先读渲染逻辑：

1. 定位该装饰的渲染分支。
2. 找抑制条件（满幅元素、锁定态、只读模式、层级过小、性能降级）。
3. 命中抑制条件 → 判 PASS 并在证据里写明抑制规则；未命中 → 才判 FAIL。

## 正向冒烟

「页面加载正常」「控制台没报错」不是证据，只说明没崩。每项验收要满足：

- 输入实际走到目标代码分支（新参数被传入、新分支被选中、新状态被写入）。
- 有一条正向可观测量证明分支生效，带具体数值。
- 反向对照可选：不触发时该可观测量应不同。
