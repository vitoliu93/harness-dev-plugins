# grill-me

不停访谈用户,直到双方对方案达成共识。把任务画成一棵**决策树**:每个决定都分叉出挂在
它下面的决定。用户确认共识达成之前不动手(硬门)。

## 事实自己查,决策才上呈

- 环境里查得到的(代码 / git / 文档 / 工具输出)自己查,永不上呈。
- 前沿问题缺环境事实时,spawn 子 agent 去找,别问用户任何你自己查得到的东西。
- **不阻塞**:跑着的探索只是一个未定的前提。只有它下游的问题要等,前沿上其余的现在就问。
- 决定是用户的:一个个摆到他面前,然后等他答。

## 盲区扫描(可选前置)

领地生疏时(叫不出受影响文件名 / 任务倚仗仓外领域知识 / 用户点名 blindspot),
建树前先扫 unknown unknowns,简报喂进决策树——它常常直接新增或剪掉分支。
做法见 [blindspot.md](references/blindspot.md)。用户单独喊 blindspot 时,交付简报即止。

## 按轮走前沿

**前沿**是所有前提已经定下来的决定——不用猜任何还没听到的答案就能问的那些。
一轮把整个前沿问完:每题编号,然后等用户回答,再进下一轮。

一轮的格式:

```
❓ **Q1** - **<问题标题>**:<问题正文,可以多段,可以带选项>

---

❓ **Q2** - **<问题标题>**:<问题正文>
```

不附推荐答案,不在题面里暗示倾向:用户的思考一看到推荐就被带偏。你自己的判断等他答完再说。
考察或摸底时同理,判分标准答完再给。

用户每轮的答案都重塑这棵树:定下来的决定把前沿往外推,解锁原本依赖它们的问题。
重算前沿,问下一轮。答案依赖本轮另一个未决问题的,属于**后面某轮**,不属于这轮。

## 收口

前沿空了就结束:树的每根枝都走过,没有东西被默默假设。产出**已确认决策**清单;
有 advanced-plan 的,它进 goal.md(锁用户意图),实现选择进 spec.md。
