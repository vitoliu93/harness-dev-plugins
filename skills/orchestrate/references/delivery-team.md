# 交付开发

改这个文件就够了，不用改插件：场景写在开头的 `use:`；一个角色一节，删掉就是不用；默认 agent 填 agents.json 里的别名，没有就换成你有的，或者删掉这行让 host 自己挑。

角色按需选，不是每次都全上。谁改的谁不查。

建议流程，参考不强制：调研摸情况，审核定验收，开发改代码，审核查，助理收尾。

## 调研 researcher

干什么：找代码、查日志、定位根因，交一份不超过十行的情况说明：改哪里、根因清不清楚、验收能不能一句话写出来、建议几个人干。
交什么：带路径或链接的证据。
不准做：改代码。
默认 agent：composer-2.5；难的用 grok-4.6。

## 开发 programmer

干什么：验收标准定好后改代码，让检查通过。发现验收没盖住的情况，报给 host，不自己扩范围。
交什么：diff，加自己跑过的检查结果。
不准做：扩范围；碰生产库和生产环境；改验收标准。
默认 agent：grok-4.6；备选 opus-5、gpt-5.6-sol。

## 审核 reviewer

干什么：开工前把“怎么算做好”写成一句话或一张清单，能写测试就写测试，前端就写“打开哪个页面、点什么、看到什么”。开发完后看代码质量、复杂度、稳不稳、哪些能删，再自己重跑检查。
交什么：验收标准；PASS 或 FAIL，附跑过的命令和输出；修改清单，每条引用被审文件的原句。
不准做：改被审的代码；采信开发自报的结果。
默认 agent：fable，思考等级 low；备选 gpt-5.6-sol，思考等级 medium。

## 助理 assistant

干什么：写文档、更新工单、推代码、部署、上传飞书这类杂活。
交什么：做完的链接或 ID。
不准做：改代码逻辑。
默认 agent：composer-2.5；备选 gpt-5.6-luna。

## 人手

验收标准一句话写不出来，先让调研补情况。改一个文件、改法一句话说得清的，开发一个人做完。
