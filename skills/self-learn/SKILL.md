# Learn Skill

从当前这次对话里把有价值的技术知识提炼出来，写成一篇中文笔记，存到 vito 的个人笔记目录。

## 笔记保存路径

`/Users/liujiaxi/Documents/programming-notes/learn_from_claude/`

文件名格式：`YYYY-MM-DD-<短标题-kebab-case>.md`

例：`2026-03-03-pipe-deadlock-and-stderr-merge.md`

## 步骤

1. 回顾当前对话，找出核心技术概念、改动原因、关键结论。如果没有实质性技术内容，直接告知用户，不写笔记。
2. **收集参考资料**：扫描对话，记录出现过的官方文档链接、外部 URL、关键文件路径——这些是知识的原始出处，写进笔记的"参考资料"节。没有就不写这节。
3. **抽象**：把业务场景剥离出来，识别其中的通用技术 pattern / 原理 / 踩坑点。业务只是引子，用一句话带过即可。笔记标题和知识点用技术概念命名，不用业务术语。
4. 如果用户通过 `$ARGUMENTS` 指定了主题，以那个主题为核心组织内容；否则自己判断本次对话的主题。
   例：`/learn pipe-deadlock` → `$ARGUMENTS = "pipe-deadlock"`，笔记标题和知识点围绕这个主题展开。
5. 按下面的模板写笔记，保存到上面的路径。
6. 写完后告诉用户文件路径。

## 笔记模板

```markdown
# <标题>

> 日期：<YYYY-MM-DD>
> 来源：和 Claude 的对话

## 背景

做什么事情时遇到了什么技术问题？一两句话，只交代技术上下文，禁止描述产品需求细节。

## 学到了什么

逐条列出本次对话里让你"哦原来如此"的知识点。每条说清楚：

- **是什么**：这个概念/机制叫什么（用通用技术语言，不绑定具体业务实体）
- **为什么**：为什么它的行为是这样的，底层原因
- **怎么用**：实际操作上要注意什么（代码示例尽量通用化，如用 `record`/`entity` 代替业务实体名；如果示例来自本次具体场景，标注"本次场景的具体应用"）

## 代码对比（如有）

把改动前后的代码片段放在这里，标注关键行。代码示例尽量通用化。

## 一句话总结

脱离业务上下文也能看懂的技术结论。

## 参考资料（如有）

对话中出现过的权威来源，直接列出，不加解释。

- 官方文档 / 链接：`<url>`
- 关键文件：`<文件路径>`（一句话说明它的作用）

如果没有，删掉这一节。

## 延伸思考（可选）

这个知识点还能用在哪些场景？有没有相关的坑值得注意？
```

## 写作风格要求

- 用中文，口语化，像给自己写备忘录一样
- 不用"首先其次最后"这种套话
- 不加 emoji
- 解释要说到"为什么"，不只说"是什么"
- 代码块里只放最关键的片段，不要贴大段无关代码
- 写完之后不要做总结性复述，直接告诉用户文件路径就行

## 禁止事项

- 不要用产品需求描述开头（如"产品需求：用户可以从候选池里丢弃..."）
- 不要以业务实体为知识点标题（如"用 status=pending 定义候选池"）
- 业务术语出现次数压到最低，能用通用术语替代就替代
- 如果一个知识点脱离业务上下文就说不清楚，那它可能不值得记录——跳过它
