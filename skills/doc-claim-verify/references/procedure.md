# 核验流程

第一个参数（文档路径）绑 `$DOC`，第二个参数（代码库根目录）绑 `$REPO`；`$REPO` 缺省取当前工作目录。
跨仓声明：把每个仓根目录追加进 `$REPOS`（空格分隔），逐仓各解一次基线。

```bash
DOC=${DOC:?文档路径}
REPO=${REPO:-$PWD}
REPOS=${REPOS:-$REPO}
OUT=${DOC_CLAIM_REPORT:-${TMPDIR:-/tmp}/doc-claim-verify.json}
```

## 1. 拆声明

一条声明 = 一个可独立证伪的事实断言。拆分标准：

- 一句话含多个断言 → 拆成多条（"A 在 B 模块，由 C 调用" → 两条）。
- 纯意图、目标、建议、风格评价 → 不入表，记进 `skipped`。
- 代码块、配置片段、命令示例中的具体值（路径、环境变量名、字段名、默认值）→ 入表。

编号 `C1..Cn`，每条保留原文引用（`quote`）与所在小节（`section`）。

## 2. 基线

```bash
git -C "$REPO" fetch --quiet
git -C "$REPO" rev-parse --short origin/<集成分支>
```

集成分支由用户指定；未指定时取仓库默认分支的 origin 侧。ref 与短 sha 写进报告头 `baseline`。
本地工作区有未推送改动时，取证仍以 origin ref 为准，把差异记进 `notes`。

## 3. 取证

按声明类型选探针：

| 声明形态 | 探针 |
|---|---|
| 某符号/函数/类存在或在某文件 | 符号搜索（代码检索工具或 `rg`） |
| 某路径存在 | `git -C "$REPO" ls-tree <ref> -- <path>` |
| 某文件内容为 X | `git -C "$REPO" show <ref>:<path>` |
| 某配置/环境变量被读取 | 全仓搜变量名，看读取点 |
| 某命令的行为 | 只读执行（`--help`、`--dry-run`、查询类子命令） |
| 跨仓声明 | 每个子仓各取一次 origin 基线，分别取证 |

evidence 记命令 + 命中片段（≤3 行）+ `file:line`。行号来自本次搜索结果，不抄文档里的行号。

## 4. 判定

- `true`：探针直接支持该断言。
- `false`：探针给出反证（符号不存在、值不一致、调用方不同）。写 `counter_evidence`。
- `undecidable`：真源不可达（外部服务、私有仓、需要写操作才能验证）、断言含主观词、或声明本身不可证伪。写 `reason`，不要为了凑数猜。

判不动就是 `undecidable`；把模糊声明强行判 `true` 是本流程唯一的致命错误。

## 5. 输出

- 边取证边追加写 `$OUT`，不要攒到最后一次性输出——长文档在单次输出里会截断。
- 声明 > 30 条：按小节分批，每批完成即写盘。
- 对话内只回：报告路径、总数、三类计数、命中率。

## 交付后

用户索取修订建议时，另起一轮，基于报告里的 `false` 条目给，不在核验轮次里混写。
